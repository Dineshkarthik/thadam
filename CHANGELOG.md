# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the project is pre-alpha (pre-1.0), any release may contain breaking changes; versioned on-disk formats refuse unknown versions rather than guessing.

## [Unreleased]

Thadam is early in its first milestone (M1 / MVP v0.1). No releases exist yet; this section summarizes what the development history has built so far. Detailed status: [docs/design/readiness.md](docs/design/readiness.md) and ARCHITECTURE.md section 21.

### Added

- **Workspace and guardrails**: eleven-member Cargo workspace (ten library crates plus the CLI), MSRV Rust 1.89, pinned toolchain, `cargo deny` policy, dependency-direction guard, nextest, CI on Linux x86_64 and ARM64.
- **Design corpus**: `ARCHITECTURE.md`, the ADR set in `docs/design/adr/` (nine accepted on 2026-10-07, including the delivery guarantees and claims register ADR-0011), owner-decision and readiness registers, and five spike reports (S1 WAL, S2 MQTT, D8 record representation, config YAML, filter language).
- **`thadam-core`**: canonical event model (times with time domains, quality status/flags, hierarchical identity, extended values, shape-shared positional records), error model with stable codes, connector traits (`Source`, `BatchSink`, `SegmentSink`), disk budget, conformance-test utilities in `thadam-testkit`.
- **`thadam-config`**: config `version: 1` — YAML loading with a strict dialect (strict booleans; no anchors/aliases/merge keys/tags; parse budget; duplicate-key errors), `${env:}`/`${file:}` secret interpolation with redaction, multi-error diagnostics with paths and line numbers, connector-kind validation through the registry, config hash (algorithm v1), memory estimate, JSON Schema export, Parquet field-ID and identity-level-ID assignment, per-sink WAL consumer policies (`required`, `max_lag`, `start_from`).
- **`thadam-wal`**: custom segmented log — one-writer group commit, `always`/`interval`/`never` fsync policies, durable cursors, retention and `on_full` (`block`/`drop_oldest`), crash recovery with torn-tail truncation, gaps surfaced to readers. **On-disk format v1 is versioned but not frozen** (ADR-0004 pending a reference-hardware re-run).
- **`thadam-transform`**: synchronous pure chains — router, JSON decode, event IDs (WAL-derived or content-derived `event_id.key`), message-level dedup with warm start, `explode` with parent paths, UCUM unit conversion (element-wise on arrays), time extraction with domains and skew flagging; steps `validate`, `on_change`, `filter`, `sample`, `enrich`, `rename`, `project`, `cast` (all config-reachable).
- **`thadam-runtime`**: source/chain/sink drivers, supervisor with component states, ordered shutdown and startup recovery, `thadam.json`/`wal.json` identity split, quarantine routing, primary-chain metric attribution.
- **`thadam-mqtt`**: MQTT 3.1.1 source — persistent sessions, acknowledge-after-commit with ordered acks, epoch-scoped ack handles, session-loss detection with resubscribe, byte-accounted queue with disconnecting guard, QoS 0 counted drops, in-process TLS/mTLS relay with rustls+`ring` (client library built without TLS features).
- **`thadam-http`**: HTTP source — `listen` mode (`POST` per message, `204` only after commit, `503` with `Retry-After` under backpressure, `413`, bearer-token auth, optional rustls+`ring` TLS, loopback bind by default) and `poll` mode (periodic GET/POST with jittered backoff and per-request timeouts; at-most-once, documented).
- **`thadam-grpc`**: gRPC source (`kind: grpc`) serving a tonic `thadam.ingest.v1.Ingest` service — unary `Publish` answers only after commit, `PublishStream` acks in order and counts committed messages, `RESOURCE_EXHAUSTED` under backpressure, `INVALID_ARGUMENT` above `max_message_bytes`, bearer-token auth, optional rustls+`ring` TLS, loopback bind by default.
- **`thadam-arrow`**: event-to-Arrow encoding with envelope/lineage columns and stable Parquet field IDs (ADR-0013 decisions: unsigned default `Native`, list element name, 16-byte schema fingerprint).
- **CLI (`thadam`)**: `validate` (with `--allow-unresolved`), `schema`, `version`, `run` (graceful signal handling, admin override flags, `--repair`), `status` against the admin API.
- **Admin API and observability**: `/healthz`, `/readyz`, `/metrics` (OpenMetrics), `/status` (components, cursors, WAL, budgets); Prometheus metrics; structured lossy logging.
- **Documentation**: README with branding and status banner, this changelog, contributing and security policies, issue/PR templates, and the mdBook user documentation under `docs/`.
- **`thadam-segments`**: the Parquet segment sink with rotation, the commit-then-ship finalize sequence (D18), the segment catalog (append-only, CRC-checked, footer rebuild on recovery), coverage markers for empty datasets, quarantine sink, and the shared-disk-budget eviction order.
- **`thadam-object-store`**: the object-store shipper as a `kind: object_store` service — oldest-first uploads from the segment catalog with bounded concurrency, deterministic keys (ADR-0013), create-if-absent with HEAD size + `thadam-sha256` verification on conflict (Fatal `sink.object_key_collision` on mismatch), multipart above a threshold, startup capability probe (conditional put, clock skew, metadata), unbounded jittered retry, local retention modes, failpoints `ship::after_put_before_mark` and `ship::mid_multipart`, and Docker tests against SeaweedFS's S3 API (`docker_s3`; public Docker Hub image pinned by tag — MinIO stopped publishing community images in late 2025).
- **Demo configuration**: `examples/edge-capture/thadam/pipeline.yaml` with six datasets, transforms, quarantine, and an S3-compatible target.
- **Demo configuration**: `examples/edge-capture/thadam/pipeline.yaml` with six datasets, transforms, quarantine, and an S3-compatible target. All six datasets carry message-level dedup now (`state` and `events` with a 50k window) so the simulator's duplicate chaos is testable on every stream.
- **`thadam-simulator`** (new workspace tool, `tools/thadam-simulator`): the seeded demo fleet — 2 sites x 3 robots publishing the six demo streams over `thadam-demo/v1/{site}/{robot}/{stream}` (QoS 1), with per-(robot, purpose) deterministic RNG (same seed, same payloads), configurable `--scale`/rates/batching, chaos knobs (malformed rate, duplicate re-publish, out-of-range motor temp, per-robot clock skew, missing timestamps, out-of-order pose), and an append-only NDJSON oracle recording every sample with its broker-PUBACK status and expected pipeline outcome (`deliver`, `filtered_debug`, `malformed`, `duplicate_of`, `state_repeat`). Subcommands: `run` (with `--drain-timeout`, `--duration`, and rate overrides) and `oracle-stats` (aggregates; `--json`). `rumqttc` follows the same pin and no-TLS-feature rules as `thadam-mqtt`.
- **`examples/edge-capture` demo stack**: Docker Compose topology for demo levels 1-2 — Mosquitto (demo broker config with persistence and raised queue limits), Toxiproxy (MQTT `21883`, S3 `29000`), the simulator image, and SeaweedFS S3 with an idempotent bucket-init step (MinIO stopped publishing community images in late 2025; SeaweedFS is the drop-in, same image as the crate's docker tests). Optional `observe` profile with provisioned Prometheus and Grafana (`edge-capture` dashboard). `Makefile` targets `up`, `up-s3`, `up-observe`, `run-native`, `query`, `oracle-stats`, `validate`, `status`, `down`, `clean`; `chaos-*` and `verify` print `added in PR18` by design. `thadam/pipeline.local.yaml` (level 1, local Parquet) and `thadam/pipeline.s3.local.yaml` (level 2, S3 through Toxiproxy) run Thadam natively (`cargo run -p thadam-cli -- run ...`); `sql/explore.sql` tours the local segments with DuckDB. README covers the walkthrough, the oracle mapping, and what this milestone does not prove.
- **Simulator tests**: unit coverage for same-seed payload determinism, topic layout, batch cadence, chaos scoping (malformed/duplicate/out-of-range/missing-ts/out-of-order/clock-skew), `on_change` expectation modeling, and oracle write/read/stats, plus an ignored Docker end-to-end test (`cargo nextest run -p thadam-simulator --run-ignored only -E 'binary(e2e_edge_capture)'`) that runs Mosquitto in a container, publishes for ~10 s, runs `thadam run` on the demo config, and checks per-dataset Parquet row counts against the oracle's acknowledged `deliver` rows (and quarantine against the oracle's `malformed` rows).
- **Connector metrics channel and ship/segment metrics** (`thadam-core`, `thadam-runtime`, `thadam-segments`, `thadam-object-store`): a typed metrics hook in `thadam-core` (`ConnectorMetric` plus the `MetricsRecorder` on `SinkContext`/`ServiceContext`) lets connectors report through the runtime's `MetricsSink` — wired at every context construction, replay included. The Prometheus exporter gains `thadam_ship_bytes_total`, `thadam_ship_uploads_total{outcome}` (`ok`/`conflict_equal`/`retry`/`fatal`), `thadam_ship_retry_age_seconds`, and `thadam_ship_upload_seconds` from the shipper, and `thadam_segment_files{state}`, `thadam_segment_bytes{state}`, and `thadam_segment_finalize_seconds` from the Parquet sink and the shipper, which republish absolute per-state catalog totals on every transition. The shipper's `ShipMetrics` trait stays as the in-crate test hook, adapted to the recorder by `RecorderShipMetrics`.


- **`thadam-mqtt` attributes**: messages now carry the normalized `topic` attribute alongside the documented `mqtt.topic`. The chain's `match.topic` filter and `{topic.N}` identity templates read `topic` (`docs/src/configuration/datasets.md`); without it, every broker message was consumed with zero matched datasets and zero written rows (PR15 end-to-end discovery).
- **`thadam replay` and `thadam inspect`** (PR17): `thadam replay <pipeline.yaml> --from <position|-45m|RFC3339> [--to ...] --sink <id> [--output <dir>]` re-runs a sink's chain over the retained WAL range into a separate directory (never the production sink directory or cursor), printing the replay id and output path. `thadam inspect wal|cursors|segments --sink|sample` are read-only views of a data directory, human-readable by default and `--json` for machine output, and work while `thadam run` holds the data directory. Supporting API: `thadam-wal` gains a read-only `inspect(dir)` that never takes the writer lock, `thadam-segments` gains a read-only `catalog::inspect(root)`, and `thadam-runtime` gains `ReplayOutput::SeparateDirAt` for a caller-chosen output path, refused inside `sinks/` and `wal/`.
### Fixed

- **`thadam-cli` crypto provider**: the composition root now installs the ring rustls crypto provider at process start. `object_store`/`reqwest` are built `rustls-no-provider` (ADR-0020), so every `thadam run` of a config with an `object_store` sink previously panicked with "No rustls crypto provider is configured" when the shipper built its S3 client (PR15 end-to-end discovery); the MQTT TLS relay builds on the same provider.
- **`thadam-object-store` probe**: the startup capability probe checked user-metadata round-trip *after* the conditional-create conflict put. On stores that ignore `If-None-Match` (observed on SeaweedFS 3.81) that second create overwrites the probe object and its attributes, so the probe reported `returns_metadata = false` for stores that do return metadata, silently degrading conflict verification to size-only. The metadata check now runs before the conflict put.
- **`thadam-config`**: the config now accepts all eight transform kinds the engine implements — `sample`, `enrich`, `rename`, `project`, and `cast` are added to `validate`, `on_change`, and `filter`, using the engine's option names.
- **`thadam-config`**: the config gains the engine's `null:` predicate test, the `on_change` `{ field, deadband }` entry form, and `unit: rfc3339` with `default_offset` for dataset `time`.
- **`thadam-config`**: `dedup` without `event_id.key` is now a validation error (`config.invalid`); it was a warning. This matches ADR-0011 D17.
- **`thadam run`**: the logging guard now stays alive for the whole run; application log lines after startup are no longer silently dropped.
- **Log-format spellings** are unified on `json`/`pretty`: config `observability.logs.format` takes those values with `text` accepted as a deprecated alias for `pretty` (validation warns), and `thadam run` without `--log-format` uses the config value (default `json`) instead of the previously hardcoded `pretty`.
