The open data plane for robotics.

Capture robotic and industrial data durably at the edge, normalize it, and deliver it to Parquet, S3-compatible object storage, and analytical databases.

Get started → Read the docs
  • Capture first, before acknowledging
  • Durable local log with fsync
  • Independent sinks per pipeline
  • Built for edge and cloud

How it works

Every accepted message is committed to one local log. Each sink then reads that log through its own chain, so a slow sink does not hold back capture or the others.

Status

Thadam is pre-alpha. Nothing is published to a package registry, and there are no release binaries yet. Available means implemented in this repository; the readiness tracker records how far each part is verified. Sink priorities: P0 local Parquet and S3-compatible object storage; P1 ClickHouse; P2 Iceberg and managed destinations.

Build from source

The Rust toolchain is pinned by rust-toolchain.toml, and rustup installs it on first use. Linux x86_64 and ARM64 are the durability targets; macOS is for development only.

git clone https://github.com/Dineshkarthik/thadam.git
cd thadam
cargo build --release -p thadam-cli
./target/release/thadam version

Latest changes

Changes land in the CHANGELOG. Design decisions are recorded as ADRs in docs/design/adr, and milestone progress is tracked in the roadmap.

Delivery claims

Guarantees are stated per hop and only where the claims register has evidence. Thadam does not claim exactly-once or zero-loss delivery end to end. For MQTT QoS 1 and 2, capture is at-least-once with acknowledgement after WAL commit. Read the full wording in delivery guarantees.
