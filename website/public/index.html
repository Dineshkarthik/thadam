The open data plane for robotics.

Capture. Transform. Buffer. Replay.

Thadam records robotic and industrial telemetry in a local durable log before it acknowledges the source. It then normalizes the data and delivers it to Parquet, S3-compatible object storage, and analytical databases.

How it works

Accepted messages are committed to one local log. Each sink reads that log through its own chain, so a slow or failed sink is isolated from the others (see ADR-0003).

Status

Thadam is in beta. Nothing is published to a package registry, and there are no release binaries yet. Available means implemented in this repository. In progress means being built. Planned means not started. The readiness tracker records how far each part has been verified.

Build from source

The Rust toolchain is pinned by rust-toolchain.toml, and rustup installs it on first use. Linux x86_64 and ARM64 are the durability targets. macOS builds are for development and make no durability claims.

git clone https://github.com/Dineshkarthik/thadam.git
cd thadam
cargo build --release -p thadam
./target/release/thadam version

Delivery claims

Guarantees are stated per hop, and only where the claims register has evidence. Thadam does not claim exactly-once or zero-loss delivery end to end. Acknowledged data survives a process crash when fsync is enabled. For MQTT QoS 1 and 2, capture is at-least-once, with acknowledgement after WAL commit. The conditions for each claim are in delivery guarantees.
